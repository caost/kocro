# macOS 매크로 텍스트 입력 앱

## 제품 이름

- 사용자에게 표시하는 앱 이름은 `Kocro`다.
- Xcode 프로젝트, 앱 타깃, Swift 모듈과 실행 파일 이름은 `Kocro`를 사용한다.
- 앱 번들 식별자는 `com.caost.Kocro`를 사용한다.

## 목적

macOS에서 사용자가 지정한 전역 단축키를 누르면 문자열, 키 조합과 딜레이로 구성한 실행 순서를 포커스된 앱에 적용한다. 한글 입력기가 활성화된 상태에서도 설정한 Unicode 문자열이 바뀌지 않아야 하며, 매크로 실행마다 외부 프로그램이나 셸 프로세스를 시작하지 않는다.

이 문서는 [크로스 플랫폼 입력 방식 검토](../../brainstorm/2026-09-04-cross-platform-macro-text-input.md) 가운데 macOS 첫 버전의 요구사항만 확정한다. 설정 창과 메뉴 바의 표시·상호작용은 [macOS 최종 화면 설계](./macos-final-ui.md)가 우선한다.

브레인스토밍 이후 사용자 합의에 따라 F13~F20과 매크로별 사용자 지정 전역 단축키를 지원한다. 일반 키 입력을 수집하는 전역 모니터는 사용하지 않고, 명시적으로 설정한 조합만 운영체제 등록 API로 수신한다.

## 지원 범위

- macOS 13 Ventura 이상을 지원한다.
- Swift와 SwiftUI로 구현한 네이티브 메뉴 바 앱을 제공한다.
- 매크로 항목을 추가·삭제·정렬할 수 있으며 항목 개수에 애플리케이션 상한을 두지 않는다. 각 항목마다 제목, 활성화 여부와 전역 단축키를 설정한다.
- 일반 키를 트리거로 지정할 때는 Command, Control, Option, Shift 중 하나 이상의 보조 키를 반드시 포함한다.
- VIA에서 사용할 수 있는 F13~F20은 보조 키 없이 사용하거나 보조 키와 결합할 수 있다.
- 각 매크로에 문자열, 키 조합과 딜레이 단계를 원하는 순서로 여러 개 설정한다.
- 여러 줄, 이모지와 조합 문자를 포함한 Unicode 문자열을 지원한다.
- 매크로 하나에 포함된 모든 문자열 단계의 합은 Swift `String.count` 기준 10,000자까지 허용한다.
- 활성화된 매크로는 수신 순서대로 직렬 실행한다.
- 로그인 시 실행 여부를 사용자가 설정할 수 있으며 기본값은 비활성화한다.

## 지원하지 않는 범위

- Windows와 Linux 앱
- F21~F35를 전역 단축키로 저장하거나 실행하는 기능
- 일반 키 하나만으로 실행하는 전역 단축키
- 키보드 장치 구분
- 클립보드 붙여넣기와 클립보드 폴백
- 부분 입력이나 대상 앱의 거부를 감지한 뒤 자동 재시도
- 네트워크 동기화, 플러그인, 셸 명령과 외부 프로세스 실행
- 비밀번호, API 키와 인증 토큰을 안전하게 보관하는 비밀 저장소
- Mac App Store 배포, Developer ID 서명과 notarization 자동화

## 프로젝트 구조

macOS 구현은 `apps/macos` 아래에 둔다. 이후 다른 운영체제 앱을 추가하더라도 macOS 프레임워크에 의존하는 구현이 공통 모듈로 유출되지 않게 한다.

```text
apps/macos/
├─ Kocro.xcodeproj
├─ Kocro/
│  ├─ App/
│  ├─ Domain/
│  ├─ Features/
│  │  ├─ MenuBar/
│  │  └─ Settings/
│  ├─ Shortcuts/
│  ├─ Input/
│  └─ Persistence/
└─ KocroTests/
```

아직 둘 이상의 운영체제 구현이 공유하는 코드가 없으므로 빈 `shared` 모듈은 만들지 않는다. 운영체제 간 설정 파일 호환도 이번 버전의 계약에 포함하지 않는다.

## 데이터 모델

### 매크로 항목과 단축키

각 매크로는 영구적인 UUID `id`로 식별한다. 설정 컬렉션에는 같은 `id`를 가진 항목이 둘 이상 있을 수 없다. 항목 순서는 설정 화면의 표시 순서이며 저장과 다시 불러오기 뒤에도 유지한다. 항목 개수에는 애플리케이션 상한을 두지 않는다. 사용자는 항목 제목을 편집할 수 있으며 입력한 문자열을 그대로 저장한다. 빈 제목의 화면 표시는 [macOS 최종 화면 설계](./macos-final-ui.md)를 따른다.

`ShortcutDefinition`은 기준 키 하나와 Command, Control, Option, Shift 보조 키 집합을 가진다. 기준 키는 값이 없음을 나타내는 `empty`, 문자, macOS 가상 키 코드 또는 F키 번호 중 하나다. 빈 실행 단축키도 `ShortcutDefinition(key: empty, modifiers: [])`로 JSON에 저장한다. 일반 키는 macOS 가상 키 코드가 안정적으로 정의된 문자·숫자·기호·탐색 키, keypad 숫자·연산 키와 F1~F12를 뜻하며 보조 키 자체, Delete, Backspace, Escape, Fn, Caps Lock과 미디어 키는 제외한다. 일반 키는 보조 키가 하나 이상 있어야 한다. F13~F20은 보조 키 없이 사용하거나 보조 키와 결합할 수 있다. F21~F35는 전역 단축키 저장과 등록 대상에서 제외한다. 활성화된 항목끼리 같은 단축키를 사용할 수 없다.

Command만 사용하는 표준 편집·파일·윈도우·앱 단축키인 Command-A/S/F/H/G/Z/X/C/V/Q/W/O/P/comma/N/M은 활성 실행 단축키로 저장하지 않는다. 이 목록은 저장 전에 검증하고 `이미 사용 중인 단축키입니다`라고 표시한다. Control, Option 또는 Shift가 함께 있는 조합과 앱별 단축키는 사전에 사용 여부를 추측하지 않고 Carbon 등록 결과로 충돌을 판정한다.

이 규칙을 추가하기 전에 저장된 표준 Command 단축키는 설정을 불러올 때 매크로의
UUID, 제목, 단축키, 실행 단계와 순서를 유지한 채 비활성화한다. 설정 파일
전체를 손상된 것으로 처리하지 않는다.

`ShortcutRegistrationIdentity`는 Carbon에 전달할 macOS 가상 키 코드와 지원하는 보조 키 비트 조합으로 구성하며 매크로 UUID는 포함하지 않는다. 활성 단축키 중복도 이 identity로 검증한다. `.letter`와 `.keyCode`처럼 모델 표현이 달라도 같은 가상 키 코드와 보조 키 조합으로 등록되면 같은 identity로 본다. 지원하지 않는 보조 키 비트는 검증에서 거부하며 identity를 만들 때 임의로 제거하지 않는다.

일반 키와 F13~F20은 포커스된 단축키 입력 컨트롤의 로컬 키 이벤트로 기록한다. 입력 컨트롤은 보조 키와 기준 키를 VIA와 비슷한 개별 토큰으로 표시한다. 전역 단축키 편집 모드에서 한 번의 새 키 입력은 기존 토큰 전체를 교체한다. 보조 키 입력 여부와 관계없이 Delete 또는 Backspace는 단축키를 비우며 Escape는 값을 유지한 채 입력 포커스를 해제한다. 키 조합 단계 편집 모드에서는 Escape, Delete와 Backspace도 실행할 키로 기록할 수 있고 별도 `지우기` 버튼으로 값을 비운다. 두 모드 모두 key repeat, 보조 키만 누른 입력과 지원하지 않는 키는 기존 값을 유지한다. 문자·숫자·기호·탐색 키와 keypad 키는 사람이 알아볼 수 있는 키 이름으로 표시한다. 일반 키 조합과 F13~F20의 전역 수신에는 `RegisterEventHotKey`를 사용한다. `IOHIDManager`, `CGEventTap`과 `NSEvent` 전역 모니터는 사용하지 않는다.

### 매크로 정의

각 `MacroDefinition`은 다음 값을 가진다.

- `id`: 항목을 식별하는 UUID
- `title`: 사용자가 편집하는 항목 제목
- `isEnabled`: 전역 단축키 등록 여부
- `shortcut`: 실행할 `ShortcutDefinition`
- `steps`: 저장된 순서대로 실행할 `MacroStep` 배열

각 `MacroStep`은 영구적인 UUID `id`와 다음 중 하나의 값을 가진다.

- `text(String)`: 여러 줄을 허용하는 Unicode 문자열
- `keys(KeyCombination)`: macOS 가상 키 코드 하나와 선택적인 보조 키 집합
- `delay(milliseconds: Int)`: 다음 실제 입력 단계 전까지 기다릴 시간

한 매크로 안에서 단계 UUID는 중복될 수 없다. 서로 다른 매크로에서는 같은 단계
UUID를 사용할 수 있다. 배열 순서와 단계 UUID는 저장과 다시
불러오기 뒤에도 유지한다. 활성화된 매크로의 `shortcut`은 유효해야 하고 `steps`에는
비어 있지 않은 문자열이나 키 조합 가운데 하나 이상이 있어야 한다. 비활성화된
매크로는 빈 실행 단축키나 활성화 조건을 충족하지 않는 실행 단축키를
`ShortcutDefinition`으로 저장할 수 있다. 토큰 문법으로 파싱할 수 없는 입력 원문은
화면 초안에만 유지하며 저장하지 않는다. 활성화 여부와 관계없이 모든 문자열 단계의 합은 10,000자를 초과할 수 없고,
딜레이는 단계마다 0~60,000ms 범위의 정수여야 하며, 단계 UUID와 매크로 UUID는 각각의
범위에서 중복될 수 없다.

`KeyCombination`은 macOS 가상 키 코드 하나와 선택적인 보조 키 집합으로 표현하며
보조 키 자체만 지정할 수 없다. F1~F20은 허용하고 F21~F35, Fn, Caps Lock과 미디어
키는 제외한다. 보조 키는 별도 키다운·키업 이벤트로 게시하지 않고 기준 키의
키다운과 키업 `CGEvent.flags`에 동일하게 설정한다. 키 조합 단계 하나는 키다운과
키업을 한 번씩 실행한다.

## 설정 저장

- 설정은 현재 사용자의 Application Support 디렉터리 아래 앱 전용 JSON 파일에 저장한다.
- 파일은 현재 사용자만 읽고 쓸 수 있는 권한으로 생성한다.
- 저장할 전체 모델을 먼저 검증한 뒤 임시 파일 작성과 원자적 교체 순서로 반영한다.
- 저장에 실패하면 실행 중인 설정과 단축키 등록을 변경하지 않고 오류를 표시한다.
- 앱 시작 시 설정 파일이 없으면 F13부터 F20까지를 순서대로 미리 지정하고 제목을 `매크로 1`부터 `매크로 8`까지 붙인 비활성 매크로 항목 8개를 초기값으로 만든다. 이 초기 항목 수는 개수 제한이 아니며 사용자는 항목을 추가하거나 삭제할 수 있다.
- 기존 JSON에 F21~F24 실행 단축키가 있으면 파일 전체를 손상으로 처리하지 않는다. 해당 항목의 UUID, 제목, 실행 단계와 배열 순서는 유지하고 `isEnabled`를 `false`, 단축키를 빈 값으로 마이그레이션한다.
- `steps` 키가 없는 기존 JSON 설정은 `text`가 비어 있지 않으면 문자열 단계로 변환하고, `trailingKey`가 있으면 그 뒤에 키 조합 단계로 변환한다. 변환할 때 생성하는 각 단계에는 해당 설정을 불러오는 시점에 새 UUID를 하나씩 할당하고 같은 매크로 안에서 중복되지 않게 한다. 생성한 UUID는 메모리에서 유지하고 다음 저장의 `steps`에 기록하므로, 저장한 뒤 다시 불러올 때 바뀌지 않는다. 두 값의 실행 순서를 바꾸거나 다른 매크로 필드를 변경하지 않는다. 다음 저장부터 `steps`만 기록한다.
- `title` 키가 없던 기존 JSON 설정은 UUID, 순서, 활성화 여부, 단축키와 실행 단계의 값을 그대로 유지하고 배열 순서에 따라 `매크로 1`, `매크로 2` 형식의 제목을 메모리에서 보완한다. 다음 저장부터 새 제목 필드를 기록한다. `title` 값이 `null`이거나 문자열이 아니면 손상된 설정으로 처리한다.
- 설정 파일을 읽거나 검증하지 못하면 이전 프로세스의 값이나 일부 값으로 단축키를 등록하지 않는다. 메뉴 바에 설정 오류를 표시하고 모든 매크로를 비활성 상태로 유지한다.
- 설정 파일을 읽거나 검증하지 못한 상태에서 설정 화면을 열면 같은 초기값과 기존 파일을 교체한다는 경고를 표시한다. 사용자가 유효한 설정을 저장하면 기존 파일을 원자적으로 교체하고 정상 상태로 복구한다.
- 매크로 문자열은 로그에 기록하지 않는다.

이 저장소는 비밀 저장소가 아니다. 설정 화면에 비밀번호, API 키와 인증 토큰을 저장하지 말라는 안내를 표시한다.

## 전역 단축키 등록

- 활성화되고 설정이 유효한 항목 가운데 일반 키 조합과 F13~F20은 `RegisterEventHotKey`로 등록한다.
- 일반 키 입력을 받는 `CGEventTap`과 `NSEvent` 전역 이벤트 모니터는 사용하지 않는다.
- 전역 단축키 수신에 Input Monitoring 권한을 요구하지 않는다.
- 단축키 등록은 항목별 성공 여부를 관리한다. 저장 시 macOS나 다른 앱과 충돌한 Carbon 단축키는 해당 항목의 `isEnabled`를 `false`로 바꿔 저장하고 실행 설정에도 활성화하지 않는다. 설정 화면에는 충돌 때문에 비활성화했다는 오류를 해당 항목에 표시한다.
- 저장 후보의 Carbon 등록은 기존 실행 설정을 유지한 채 준비한다. 최종 후보에도 같은 `ShortcutRegistrationIdentity`가 있으면 기존 등록을 재사용하고 커밋 시 registration ID와 매크로 UUID의 연결만 바꾼다. 이를 통해 항목 사이의 단축키 교환과 비활성화한 항목의 단축키 이전을 앱 자신의 충돌로 처리하지 않는다. 기존 등록에 없는 단축키만 임시 registration ID로 새로 확보하며, 준비 중 해당 ID의 이벤트가 들어오면 실행 스냅샷에 연결하지 않고 무시한다. 충돌 항목을 비활성화한 최종 후보의 원자 저장이 성공한 뒤 실행 스냅샷과 registration ID 매핑을 한 번에 교체하고 더 이상 쓰지 않는 등록을 해제한다. 저장에 실패하면 새로 준비한 등록만 해제하며 기존 실행 설정과 등록은 유지한다.
- 설정 저장이 성공하면 변경된 항목의 등록 상태를 새 설정과 일치시킨다.
- 앱 종료 시 등록한 모든 전역 단축키를 해제한다.
- 단축키 이벤트에는 외부에서 전달받은 문자열을 포함하지 않는다. 앱은 등록 ID로 매크로 항목을 찾고 저장된 설정에서 실행 내용을 조회한다.

## 입력 실행

- 텍스트 입력은 Core Graphics의 `CGEvent` 키보드 이벤트에 Unicode 문자열을 지정해 수행한다.
- 가상 키 코드를 문자로 변환하는 현재 키보드 배열이나 입력기에 의존하지 않는다.
- 긴 문자열은 필요한 경우 여러 이벤트로 나눌 수 있다. 분할 과정에서 UTF-16 surrogate pair나 확장 자소 클러스터를 나누지 않는다.
- Unicode 텍스트 이벤트는 트리거 단축키의 보조 키 상태가 합쳐지지 않도록 빈 `CGEvent.flags`로 게시한다.
- 하나의 단축키 이벤트를 받으면 그 시점의 유효한 실행 단계 배열을 실행 요청에 값으로 복사한다. 이후 설정 변경은 이미 대기 중인 요청에 영향을 주지 않는다.
- 실행 요청은 하나의 직렬 큐에서 수신 순서대로 처리한다. 앞선 요청이 끝나기 전에 받은 요청도 버리지 않는다.
- 문자열과 키 조합 단계는 배열 순서대로 `CGEvent` 구간을 만든다. 키 조합의 키다운과 키업은 하나의 구간이며 두 이벤트 사이에는 딜레이를 적용하지 않는다.
- 딜레이 단계는 앞의 실제 입력 구간 게시가 끝난 뒤 다음 실제 입력 구간을 게시하기 전에 적용한다. 연속된 딜레이는 합산하고, 앞이나 뒤에 실제 입력 구간이 없는 딜레이는 기다리지 않는다.
- 한 요청에 필요한 모든 `CGEvent`를 먼저 생성한다. 이벤트를 하나라도 생성하지 못하면 아무 이벤트도 게시하지 않고 딜레이도 적용하지 않는다.
- 생성이 끝나면 각 구간의 이벤트를 순서대로 게시하고 필요한 딜레이를 적용한다. 마지막 구간의 게시 API 호출이 끝난 뒤 다음 요청을 시작한다.
- 매크로 실행 경로에서 외부 프로그램, 셸 프로세스와 네트워크 요청을 시작하지 않는다.

`CGEvent` 게시 API는 이벤트 전달 결과나 포커스된 앱이 문자열을 실제로 반영했는지 응답하지 않는다. 따라서 이벤트를 생성해 게시 API 호출을 마친 상태만 `게시 요청 완료`로 표시한다. 권한 없음, 문자열 생성 실패처럼 호출 전에 확인할 수 있는 오류는 구체적인 오류 종류로 표시한다. 대상 앱의 최종 입력 성공을 의미하는 `입력 성공`이나 관찰할 수 없는 `게시 실패` 상태는 표시하지 않는다.

## 권한

- 앱 시작 시 현재 프로세스의 Accessibility 신뢰 상태를 확인한다.
- 권한이 없으면 매크로 실행을 시도하지 않고 메뉴 바에 `권한 필요` 상태를 표시한다.
- 사용자가 명시적으로 선택하는 버튼으로 시스템 권한 안내를 요청하고 시스템 설정을 열 수 있게 한다.
- 권한 안내 요청은 비동기이므로 요청 직후 권한이 부여됐다고 간주하지 않는다. 앱이 활성화되거나 메뉴를 다시 열 때 상태를 다시 확인한다.
- 관리자 권한으로 앱을 다시 실행하도록 요구하지 않는다.
- Screen Recording, Full Disk Access와 Automation 권한을 요구하지 않는다.

## 화면 동작

### 메뉴 바 컨텍스트 메뉴

메뉴 항목의 표시값과 상호작용은 [macOS 최종 화면 설계](./macos-final-ui.md)가 우선한다.

메뉴 바 화면은 다음 항목을 제공한다.

- 전체 상태: 준비됨, Accessibility 권한 필요, 설정 오류
- Carbon으로 활성화되고 등록에 성공한 매크로 수
- 마지막 실행 결과: 매크로 식별값과 단축키, 게시 요청 완료 또는 호출 전에 확인한 오류 종류, 시각
- Accessibility 권한 안내 동작
- 설정 열기
- About 열기
- 앱 종료

마지막 실행 결과에는 매크로 문자열과 포커스된 앱 이름을 포함하지 않는다. 시스템 알림은 기본 실행 결과 표시 수단으로 사용하지 않는다.

전체 상태가 둘 이상 성립하면 설정 오류, Accessibility 권한 필요, 준비됨 순서로 하나를 표시한다. 단축키 일부의 등록 충돌은 전체 상태를 설정 오류로 바꾸지 않고 해당 항목의 오류로 표시한다.

### 설정

- 설정 화면은 `매크로`와 `일반` 두 영역으로 나눈다. `매크로`는 항목 편집을, `일반`은 로그인 시 실행과 권한 상태·설정 열기를 제공한다.
- 매크로 항목을 저장된 순서로 표시하고 새 항목 추가, 기존 항목 삭제와 순서 변경을 제공한다.
- 각 항목에서 제목, 활성화 여부, 전역 단축키와 문자열·키 조합·딜레이 실행 순서를 편집할 수 있다.
- 일반 키와 F1~F20 전역 단축키 및 키 조합 단계는 포커스된 토큰 입력 컨트롤에서 한 번의 키 입력 또는 키 조합을 기록한다. F21~F35는 선택, 직접 입력과 기록에서 제외한다.
- 현재 글자 수와 10,000자 제한을 표시한다.
- 빈 문자열, 길이 초과, 유효하지 않거나 중복된 단축키와 단축키 등록 충돌을 항목별로 표시한다.
- 저장 버튼을 누르기 전까지 실행 중인 설정을 변경하지 않는다.
- 저장 검증에 실패하면 어떤 키를 수정해야 하는지 표시하고 유효한 기존 설정은 계속 사용한다.
- Carbon 충돌로 자동 비활성화된 안내는 해당 저장 결과와 함께 표시하고 다음 저장 시 새 결과로 교체한다.

### About

- 메뉴 바의 `Kocro 정보` 항목은 macOS 표준 About 패널을 연다.
- About 패널은 앱 아이콘, 표시 이름, 버전과 빌드 번호를 앱 번들 메타데이터에서 표시한다.

## 실행 흐름

```text
사용자 지정 전역 단축키
        │
        ▼
등록된 트리거인지 확인
        │
        ▼
현재 실행 단계 배열 복사
        │
        ▼
직렬 실행 큐에 추가
        │
        ▼
Accessibility 권한 확인
        │
        ▼
다음 문자열 또는 키 조합 구간 게시
        │
        ▼
설정된 경우 다음 구간 전까지 대기
        │
        ▼
문자열을 제외한 실행 결과 갱신
```

등록되지 않은 단축키, 비활성화된 항목, 실제 입력 단계가 없는 항목은 아무 이벤트도 게시하지 않는다.

## 오류 처리

| 상황 | 동작 |
| --- | --- |
| 설정 파일 없음 | 모두 비활성화된 기본 설정 생성 |
| 설정 읽기·검증 실패 | 모든 매크로 비활성화, 설정 오류 표시 |
| 설정 저장 실패 | 기존 실행 설정 유지, 저장 오류 표시 |
| 단축키 등록 충돌 | 충돌한 항목의 `isEnabled`를 `false`로 바꿔 저장하고 실행 설정에서도 비활성화, 다른 항목 유지 |
| 기존 설정의 F21~F24 실행 단축키 | 항목 내용과 순서를 유지하고 비활성·빈 단축키로 마이그레이션 |
| Accessibility 권한 없음 | 입력 이벤트를 게시하지 않고 권한 필요 표시 |
| 이벤트 생성 실패 | 해당 요청 중단, 다음 요청 처리 |
| 이벤트 게시 후 대상 앱이 무시 | 감지하거나 재시도하지 않음 |
| 앱 종료 | 등록한 단축키와 실행 리소스 해제 |

이벤트는 한 요청의 전체 묶음을 생성한 뒤 게시하므로 생성 실패 시 어떤 단계도 게시하거나 대기하지 않는다. 게시 API 호출 후 대상 앱의 반영 결과는 알 수 없으므로 같은 실행 단계를 다시 입력하지 않는다. 클립보드 폴백도 수행하지 않는다.

## 보안과 개인정보 보호

- 사용자가 활성화한 항목의 유효한 전역 단축키만 등록한다.
- 키 입력 전체를 감시하지 않는다.
- 입력 문자열, 포커스된 앱과 기존 클립보드 내용을 로그에 남기지 않는다.
- 클립보드를 읽거나 변경하지 않는다.
- 설정에 저장된 문자열과 키 조합만 입력하며 트리거에서 임의 문자열이나 명령을 받지 않는다.
- 네트워크 통신, 플러그인 로딩과 셸 실행 기능을 제공하지 않는다.
- 관리자 권한을 요청하지 않는다.
- 잠금 화면과 macOS가 합성 입력을 차단하는 대상은 지원하지 않는다.

## 테스트 요구사항

운영체제 API를 감싼 인터페이스를 두어 다음 동작을 단위 테스트한다.

- 매크로 UUID 중복 금지, 항목 순서 보존, 일반 키 범위와 보조 키 규칙, F13~F20의 단독·보조 키 조합 허용, F21~F35 거부
- `ShortcutRegistrationIdentity`가 같은 서로 다른 모델 표현의 활성 단축키 중복 거부
- 제목이 없는 이전 JSON 설정의 무손실 마이그레이션과 편집한 제목의 round-trip
- 최초 실행의 비활성 기본 항목 8개와 순서 기반 제목
- 기존 F21~F24 항목의 내용·순서를 유지하는 비활성·빈 단축키 마이그레이션
- 매크로와 단계 UUID 중복, 실제 입력 단계가 없는 활성 매크로, 중복 단축키, 단계별 딜레이 범위와 전체 문자열 10,000자 제한 검증
- 문자열·키 조합·딜레이 단계의 추가·삭제·순서 변경과 종류별 편집
- 여러 키 조합과 딜레이를 포함한 `steps`의 UUID·순서·설정값 round-trip
- 기존 `text`와 `trailingKey` JSON을 같은 실행 순서의 `steps`로 마이그레이션
- 설정 저장 실패 시 기존 실행 설정 유지
- 활성화된 항목의 단축키만 등록하고 종료 시 해제
- 단축키 등록 일부 실패가 다른 항목에 영향을 주지 않음
- 저장 후보의 Carbon 충돌 항목만 비활성화하고 저장 실패 시 기존 등록과 실행 스냅샷을 유지함
- 기존 Carbon 단축키의 항목 간 교환·이전, 준비 중 임시 registration ID 이벤트 무시, 준비 중 기존 registration ID의 기존 스냅샷 실행
- 실행 요청의 FIFO 순서와 단축키 수신 시점의 전체 실행 단계 배열 복사
- Unicode 분할이 surrogate pair와 확장 자소 클러스터를 나누지 않음
- 문자열과 키 조합 이벤트의 목록 순서, 키다운·키업의 동일한 보조 키 flags, 구간 사이 딜레이와 마지막 딜레이 생략, 생성 실패 시 게시·대기하지 않음
- 권한이 없거나 실행 단계 배열 조회가 실패하면 이벤트를 게시하지 않음
- 오류와 실행 상태에 매크로 문자열이 포함되지 않음
- 손상된 설정 로드 시 실행 설정 비활성화와 교체 경고 초안, 전체 상태 우선순위
- Unicode 텍스트 이벤트의 빈 `CGEvent.flags`
- 로그인 시 실행의 기본값이 비활성이고 사용자가 설정과 해제를 전환할 수 있음
- 단축키 토큰 표시·전체 교체·삭제와 일반 설정·표준 About 동작

실제 macOS 환경에서는 다음 대상을 수동 통합 검증한다.

- TextEdit
- Safari 또는 Chromium 입력 필드
- Terminal
- VS Code
- 한글 입력기가 활성화된 상태
- 여러 단축키를 빠르게 누른 상태
- 문자열·키 조합·딜레이가 섞인 실행 순서
- Accessibility 권한이 없거나 실행 중 철회된 상태
- 다른 앱이 같은 전역 단축키를 사용하는 상태

## 수용 기준

1. macOS 13 이상에서 메뉴 바 앱이 실행되고 설정 화면을 열 수 있다.
2. 매크로 항목을 개수 제한 없이 추가·삭제·정렬할 수 있고, 항목별 제목, 활성화 여부, 유효한 전역 단축키와 문자열·키 조합·딜레이 실행 순서를 저장하고 다시 불러올 수 있다. 모든 문자열 단계의 합은 최대 10,000자이며 제목이나 `steps`가 없는 기존 설정은 다른 필드와 실행 순서를 바꾸지 않고 마이그레이션한다.
3. 일반 키 단축키에는 하나 이상의 보조 키를 요구하고 F13~F20은 보조 키 없이 사용하거나 보조 키와 결합할 수 있다. 보조 키가 있는 F1~F12를 포함한 일반 키 조합과 F13~F20은 `RegisterEventHotKey`로 등록한다. F21~F35는 저장·실행하지 않으며 Input Monitoring 권한을 요청하지 않는다.
4. 한글 입력기가 활성화된 TextEdit에서 한글, 영문, 여러 줄, 이모지와 조합 문자가 설정과 동일하게 게시된다.
5. 문자열과 키 조합은 목록 순서대로 게시되고 딜레이는 앞 구간 완료 후 다음 구간 전에만 적용된다. 한 요청의 이벤트 생성에 실패하면 해당 요청의 이벤트를 하나도 게시하거나 대기하지 않는다.
6. 빠르게 받은 여러 단축키가 누락되거나 순서가 바뀌지 않는다.
7. Accessibility 권한 없음, 시작 시 설정 로드·검증 오류 또는 단축키 등록 실패 상태의 해당 항목에서는 이벤트를 게시하지 않는다. 편집 내용 저장 실패 시에는 저장 직전부터 유효했던 실행 설정과 트리거 상태를 유지하며, 해당 기존 설정의 단축키는 계속 실행할 수 있다.
8. 직접 입력 실패 시 클립보드 폴백이나 전체 실행 순서 자동 재시도를 수행하지 않는다.
9. 로그와 화면 상태에 매크로 문자열이나 포커스된 앱 이름이 남지 않는다.
10. Release 빌드와 100자의 ASCII 문자열을 사용하고, 실행 큐가 빈 상태에서 이전 요청의 게시 API 호출이 끝난 뒤 다음 요청을 시작하는 방식으로 100회 측정해 단축키 수신부터 마지막 게시 API 호출 완료까지의 p50과 p95를 검증 기록에 남긴다. 큐 대기 시간과 대상 앱의 화면 반영 시간은 측정에서 제외하며 실행마다 외부 프로세스를 시작하지 않는다. 첫 버전은 환경별 기준값을 수집하는 단계이므로 통과 임계값을 두지 않는다.
11. 로그인 시 실행은 기본적으로 비활성이고, 일반 설정에서 설정하거나 해제한 상태가 macOS 로그인 항목에 반영된다.
12. 단축키 입력은 보조 키와 기준 키를 개별 토큰으로 표시하고 한 번의 입력으로 교체하거나 Delete·Backspace로 비울 수 있다.
13. 저장 후보의 Carbon 단축키가 충돌하면 해당 항목만 비활성화해 저장하고, 저장 자체가 실패하면 기존 실행 설정과 등록을 유지한다.
14. 설정 화면에서 매크로와 일반 설정을 구분해 편집할 수 있고 메뉴 바에서 macOS 표준 About 패널을 열 수 있다.
