# macOS 매크로 텍스트 입력 앱

## 제품 이름

- 사용자에게 표시하는 앱 이름은 `Kocro`다.
- Xcode 프로젝트, 앱 타깃, Swift 모듈과 실행 파일 이름은 `Kocro`를 사용한다.
- 앱 번들 식별자는 `com.caost.Kocro`를 사용한다.

## 목적

macOS에서 사용자가 지정한 전역 단축키를 누르면 미리 설정한 텍스트와 선택적인 후속 키 입력을 포커스된 앱에 보낸다. 한글 입력기가 활성화된 상태에서도 설정한 Unicode 문자열이 바뀌지 않아야 하며, 매크로 실행마다 외부 프로그램이나 셸 프로세스를 시작하지 않는다.

이 문서는 [크로스 플랫폼 입력 방식 검토](../../brainstorm/2026-09-04-cross-platform-macro-text-input.md) 가운데 macOS 첫 버전의 요구사항만 확정한다.

브레인스토밍 이후 사용자 합의에 따라 F13~F24 전용안에서 매크로별 사용자 지정 전역 단축키로 범위를 넓혔다. 일반 키 입력을 수집하는 전역 모니터는 사용하지 않고, 명시적으로 설정한 조합만 운영체제 등록 API로 수신한다.

## 지원 범위

- macOS 13 Ventura 이상을 지원한다.
- Swift와 SwiftUI로 구현한 네이티브 메뉴 바 앱을 제공한다.
- 매크로 항목을 추가·삭제할 수 있으며 항목 개수에 애플리케이션 상한을 두지 않는다. 각 항목마다 활성화 여부와 전역 단축키를 설정한다.
- 일반 키를 트리거로 지정할 때는 Command, Control, Option, Shift 중 하나 이상의 보조 키를 반드시 포함한다.
- VIA에서 사용할 수 있는 F13부터 F24까지는 보조 키 없이 트리거로 지정할 수 있다.
- 각 매크로에 하나의 고정 문자열과 선택적인 후속 키 입력을 설정한다.
- 여러 줄, 이모지와 조합 문자를 포함한 Unicode 문자열을 지원한다.
- 매크로 하나의 문자열은 Swift `String.count` 기준 10,000자까지 허용한다.
- 활성화된 매크로는 수신 순서대로 직렬 실행한다.
- 로그인 시 실행 여부를 사용자가 설정할 수 있으며 기본값은 비활성화한다.

## 지원하지 않는 범위

- Windows와 Linux 앱
- F25~F35를 전역 단축키로 등록하는 기능
- 일반 키 하나만으로 실행하는 전역 단축키
- 키보드 장치 구분
- 클립보드 붙여넣기와 클립보드 폴백
- 부분 입력이나 대상 앱의 거부를 감지한 뒤 자동 재시도
- 네트워크 동기화, 플러그인, 셸 명령과 외부 프로세스 실행
- 비밀번호, API 키와 인증 토큰을 안전하게 보관하는 비밀 저장소
- Mac App Store 배포, Developer ID 서명과 notarization 자동화

## 프로젝트 구조

macOS 구현은 `apps/macos` 아래에 둔다. 이후 다른 운영체제 앱을 추가하더라도 macOS 프레임워크에 의존하는 구현이 공통 모듈로 유출되지 않게 한다.

```text
apps/macos/
├─ Kocro.xcodeproj
├─ Kocro/
│  ├─ App/
│  ├─ Domain/
│  ├─ Features/
│  │  ├─ MenuBar/
│  │  └─ Settings/
│  ├─ Shortcuts/
│  ├─ Input/
│  └─ Persistence/
└─ KocroTests/
```

아직 둘 이상의 운영체제 구현이 공유하는 코드가 없으므로 빈 `shared` 모듈은 만들지 않는다. 운영체제 간 설정 파일 호환도 이번 버전의 계약에 포함하지 않는다.

## 데이터 모델

### 매크로 항목과 단축키

각 매크로는 영구적인 UUID `id`로 식별한다. 설정 컬렉션에는 같은 `id`를 가진 항목이 둘 이상 있을 수 없다. 항목 순서는 설정 화면의 표시 순서이며 저장과 다시 불러오기 뒤에도 유지한다. 항목 개수에는 애플리케이션 상한을 두지 않는다.

`ShortcutDefinition`은 기준 키 하나와 Command, Control, Option, Shift 보조 키 집합을 가진다. 일반 키는 macOS 가상 키 코드가 안정적으로 정의된 문자·숫자·기호·탐색 키와 F1~F12를 뜻하며 보조 키 자체, Fn, Caps Lock과 미디어 키는 제외한다. 일반 키는 보조 키가 하나 이상 있어야 한다. F13~F20은 보조 키 없이 사용하거나 보조 키와 결합할 수 있다. F21~F24는 보조 키와 결합하지 않은 단독 트리거만 지원하고 F25~F35는 전역 단축키 등록 대상에서 제외한다. 활성화된 항목끼리 같은 단축키를 사용할 수 없다.

일반 키와 F13~F20은 포커스된 단축키 입력 컨트롤의 로컬 키 이벤트로 기록한다. F21~F24는 로컬 이벤트의 가상 키 코드에 의존하지 않고 설정 화면의 전용 선택 컨트롤에서 지정한다. 일반 키 조합과 F13~F20의 전역 수신에는 `RegisterEventHotKey`를 사용하고, F21~F24에는 `IOHIDManager`의 입력 요소 매칭을 사용한다. `CGEventTap`과 `NSEvent` 전역 모니터는 사용하지 않는다.

### 매크로 정의

각 `MacroDefinition`은 다음 값을 가진다.

- `id`: 항목을 식별하는 UUID
- `isEnabled`: 전역 단축키 등록 여부
- `shortcut`: 실행할 `ShortcutDefinition`
- `text`: 입력할 Unicode 문자열
- `trailingKey`: 없음, Enter, Space, Tab 또는 사용자 지정 키 입력

활성화된 매크로의 `shortcut`과 `text`는 비어 있을 수 없고 `text`는 10,000자를 초과할 수 없다. 비활성화된 매크로는 비어 있거나 아직 유효하지 않은 단축키와 문자열을 편집 상태로 보존할 수 있지만, 비활성 상태에서도 10,000자 제한과 UUID 중복 금지는 동일하게 적용한다.

사용자 지정 `trailingKey`는 macOS 가상 키 코드 하나와 선택적인 보조 키 집합으로 표현하며 보조 키 자체만 지정할 수 없다. F1~F20은 사용자 지정 후속 키로 허용하고 F21~F35, Fn, Caps Lock과 미디어 키는 제외한다. 후속 키의 보조 키는 별도 키다운·키업 이벤트로 게시하지 않고 기준 키의 키다운과 키업 `CGEvent.flags`에 동일하게 설정한다. 후속 키 입력은 한 번만 실행한다.

## 설정 저장

- 설정은 현재 사용자의 Application Support 디렉터리 아래 앱 전용 JSON 파일에 저장한다.
- 파일은 현재 사용자만 읽고 쓸 수 있는 권한으로 생성한다.
- 저장할 전체 모델을 먼저 검증한 뒤 임시 파일 작성과 원자적 교체 순서로 반영한다.
- 저장에 실패하면 실행 중인 설정과 단축키 등록을 변경하지 않고 오류를 표시한다.
- 앱 시작 시 설정 파일이 없으면 F13부터 F24까지를 순서대로 미리 지정한 비활성 매크로 항목 12개를 초기값으로 만든다. 이 초기 항목 수는 개수 제한이 아니며 사용자는 항목을 추가하거나 삭제할 수 있다.
- 설정 파일을 읽거나 검증하지 못하면 이전 프로세스의 값이나 일부 값으로 단축키를 등록하지 않는다. 메뉴 바에 설정 오류를 표시하고 모든 매크로를 비활성 상태로 유지한다.
- 설정 파일을 읽거나 검증하지 못한 상태에서 설정 화면을 열면 같은 초기값과 기존 파일을 교체한다는 경고를 표시한다. 사용자가 유효한 설정을 저장하면 기존 파일을 원자적으로 교체하고 정상 상태로 복구한다.
- 매크로 문자열은 로그에 기록하지 않는다.

이 저장소는 비밀 저장소가 아니다. 설정 화면에 비밀번호, API 키와 인증 토큰을 저장하지 말라는 안내를 표시한다.

## 전역 단축키 등록

- 활성화되고 설정이 유효한 항목 가운데 일반 키 조합과 F13~F20은 `RegisterEventHotKey`로 등록한다.
- 활성화된 F21~F24가 하나 이상 있으면 `IOHIDManagerSetInputValueMatchingMultiple`로 HID Keyboard/Keypad usage page의 F21~F24 중 필요한 입력 요소만 매칭한다. 다른 키 입력 요소는 앱의 콜백으로 전달하지 않는다.
- `IOHIDManager` 콜백은 키를 누른 값만 트리거로 처리하고 키를 뗀 값과 같은 키의 중복 press 상태를 무시한다.
- F21~F24 수신은 키를 독점하거나 원래 키 이벤트를 제거하지 않는다. 포커스된 앱이나 다른 프로그램이 같은 키를 처리할 수 있으며 앱은 이를 충돌로 감지할 수 없다.
- 일반 키 입력을 받는 `CGEventTap`과 `NSEvent` 전역 이벤트 모니터는 사용하지 않는다.
- `RegisterEventHotKey`로 처리하는 단축키만 활성화하면 Input Monitoring 권한을 요구하지 않는다. F21~F24가 하나 이상 활성화되면 Input Monitoring 권한이 필요하다.
- 단축키 등록은 항목별 성공 여부를 관리한다. macOS나 다른 앱과 충돌한 단축키는 실행하지 않고 해당 항목의 등록 실패를 설정 화면에 표시한다.
- F21~F24는 등록 충돌 대신 HID 접근 권한과 모니터 시작 성공 여부를 항목 상태로 표시한다.
- 설정 저장이 성공하면 변경된 항목의 등록 상태를 새 설정과 일치시킨다.
- 앱 종료 시 등록한 모든 전역 단축키를 해제한다.
- 단축키 이벤트에는 외부에서 전달받은 문자열을 포함하지 않는다. 앱은 등록 ID로 매크로 항목을 찾고 저장된 설정에서 실행 내용을 조회한다.

## 텍스트 입력

- 텍스트 입력은 Core Graphics의 `CGEvent` 키보드 이벤트에 Unicode 문자열을 지정해 수행한다.
- 가상 키 코드를 문자로 변환하는 현재 키보드 배열이나 입력기에 의존하지 않는다.
- 긴 문자열은 필요한 경우 여러 이벤트로 나눌 수 있다. 분할 과정에서 UTF-16 surrogate pair나 확장 자소 클러스터를 나누지 않는다.
- 하나의 단축키 이벤트를 받으면 그 시점의 유효한 매크로 문자열과 후속 키 입력을 실행 요청에 복사한다. 이후 설정 변경은 이미 대기 중인 요청에 영향을 주지 않는다.
- 실행 요청은 하나의 직렬 큐에서 수신 순서대로 처리한다. 앞선 요청이 끝나기 전에 받은 요청도 버리지 않는다.
- 한 요청에 필요한 텍스트와 후속 키의 `CGEvent`를 모두 먼저 생성한다. 이벤트를 하나라도 생성하지 못하면 아무 이벤트도 게시하지 않고 후속 키도 실행하지 않는다.
- 생성이 끝나면 텍스트 이벤트를 순서대로 게시하고, 설정된 경우 후속 키의 키다운·키업 이벤트를 한 번 게시한다. 모든 게시 API 호출이 끝난 뒤 다음 요청을 시작한다.
- 매크로 실행 경로에서 외부 프로그램, 셸 프로세스와 네트워크 요청을 시작하지 않는다.

`CGEvent` 게시 API는 이벤트 전달 결과나 포커스된 앱이 문자열을 실제로 반영했는지 응답하지 않는다. 따라서 이벤트를 생성해 게시 API 호출을 마친 상태만 `게시 요청 완료`로 표시한다. 권한 없음, 문자열 생성 실패처럼 호출 전에 확인할 수 있는 오류는 구체적인 오류 종류로 표시한다. 대상 앱의 최종 입력 성공을 의미하는 `입력 성공`이나 관찰할 수 없는 `게시 실패` 상태는 표시하지 않는다.

## 권한

- 앱 시작 시 현재 프로세스의 Accessibility 신뢰 상태를 확인한다.
- 권한이 없으면 매크로 실행을 시도하지 않고 메뉴 바에 `권한 필요` 상태를 표시한다.
- 사용자가 명시적으로 선택하는 버튼으로 시스템 권한 안내를 요청하고 시스템 설정을 열 수 있게 한다.
- 권한 안내 요청은 비동기이므로 요청 직후 권한이 부여됐다고 간주하지 않는다. 앱이 활성화되거나 메뉴를 다시 열 때 상태를 다시 확인한다.
- 관리자 권한으로 앱을 다시 실행하도록 요구하지 않는다.
- F21~F24가 하나 이상 활성화되면 Input Monitoring 접근 상태를 확인한다. 권한이 없으면 해당 항목을 실행하지 않고 사용자가 명시적으로 선택하는 버튼으로 권한을 요청하거나 시스템 설정을 열 수 있게 한다.
- F21~F24를 모두 비활성화하면 Input Monitoring 권한을 요청하지 않고 실행 중인 HID 모니터를 닫는다.
- Screen Recording, Full Disk Access와 Automation 권한을 요구하지 않는다.

## 화면 동작

### 메뉴 바

메뉴 바 화면은 다음 항목을 제공한다.

- 전체 상태: 준비됨, Accessibility 권한 필요, Input Monitoring 권한 필요, 설정 오류
- 활성화되고 등록에 성공한 매크로 수
- 마지막 실행 결과: 매크로 UUID의 앞 8자리와 단축키, 게시 요청 완료 또는 호출 전에 확인한 오류 종류, 시각
- Accessibility와 조건부 Input Monitoring 권한 안내 동작
- 설정 열기
- 로그인 시 실행 설정
- 앱 종료

마지막 실행 결과에는 매크로 문자열과 포커스된 앱 이름을 포함하지 않는다. 시스템 알림은 기본 실행 결과 표시 수단으로 사용하지 않는다.

전체 상태가 둘 이상 성립하면 설정 오류, Accessibility 권한 필요, Input Monitoring 권한 필요, 준비됨 순서로 하나를 표시한다. Accessibility 권한은 모든 매크로 게시에 필요하므로 F21~F24에만 필요한 Input Monitoring보다 먼저 표시한다. 단축키 일부의 등록 충돌이나 HID 모니터 시작 실패는 전체 상태를 설정 오류로 바꾸지 않고 해당 항목의 오류로 표시한다.

### 설정

- 매크로 항목을 저장된 순서로 표시하고 새 항목 추가, 기존 항목 삭제와 순서 변경을 제공한다.
- 각 항목에서 활성화 여부, 전역 단축키, 여러 줄 문자열과 후속 키 입력을 편집할 수 있다.
- 일반 키와 F1~F20 전역 단축키 및 사용자 지정 후속 키는 포커스된 입력 컨트롤에서 한 번의 키 입력 또는 키 조합을 기록한다. F21~F24 전역 단축키는 같은 항목의 전용 선택 컨트롤에서 지정한다.
- 현재 글자 수와 10,000자 제한을 표시한다.
- 빈 문자열, 길이 초과, 유효하지 않거나 중복된 단축키와 단축키 등록 충돌을 항목별로 표시한다.
- 저장 버튼을 누르기 전까지 실행 중인 설정을 변경하지 않는다.
- 저장 검증에 실패하면 어떤 키를 수정해야 하는지 표시하고 유효한 기존 설정은 계속 사용한다.

## 실행 흐름

```text
사용자 지정 전역 단축키
        │
        ▼
등록된 트리거인지 확인
        │
        ▼
현재 문자열과 후속 키 입력 복사
        │
        ▼
직렬 실행 큐에 추가
        │
        ▼
Accessibility 권한 확인
        │
        ▼
CGEvent Unicode 이벤트 게시
        │
        ▼
선택된 후속 키의 키다운·키업 게시
        │
        ▼
문자열을 제외한 실행 결과 갱신
```

등록되지 않은 단축키, 비활성화된 항목, 유효한 문자열을 찾지 못한 항목은 아무 이벤트도 게시하지 않는다.

## 오류 처리

| 상황 | 동작 |
| --- | --- |
| 설정 파일 없음 | 모두 비활성화된 기본 설정 생성 |
| 설정 읽기·검증 실패 | 모든 매크로 비활성화, 설정 오류 표시 |
| 설정 저장 실패 | 기존 실행 설정 유지, 저장 오류 표시 |
| 단축키 등록 충돌 | 충돌한 항목만 실행 불가로 표시, 다른 항목 유지 |
| F21~F24 사용 중 Input Monitoring 권한 없음 | 해당 항목은 실행하지 않고 권한 필요 표시 |
| HID 모니터 시작 실패 | F21~F24 항목을 실행 불가로 표시, Carbon 단축키 유지 |
| Accessibility 권한 없음 | 입력 이벤트를 게시하지 않고 권한 필요 표시 |
| 이벤트 생성 실패 | 해당 요청 중단, 다음 요청 처리 |
| 이벤트 게시 후 대상 앱이 무시 | 감지하거나 재시도하지 않음 |
| 앱 종료 | 등록한 단축키와 실행 리소스 해제 |

이벤트는 한 요청의 전체 묶음을 생성한 뒤 게시하므로 생성 실패 시 텍스트와 후속 키를 모두 게시하지 않는다. 게시 API 호출 후 대상 앱의 반영 결과는 알 수 없으므로 같은 문자열이나 후속 키를 다시 입력하지 않는다. 클립보드 폴백도 수행하지 않는다.

## 보안과 개인정보 보호

- 사용자가 활성화한 항목의 유효한 전역 단축키만 등록한다.
- 키 입력 전체를 감시하지 않는다.
- 입력 문자열, 포커스된 앱과 기존 클립보드 내용을 로그에 남기지 않는다.
- 클립보드를 읽거나 변경하지 않는다.
- 설정에 저장된 문자열만 입력하며 트리거에서 임의 문자열이나 명령을 받지 않는다.
- 네트워크 통신, 플러그인 로딩과 셸 실행 기능을 제공하지 않는다.
- 관리자 권한을 요청하지 않는다.
- 잠금 화면과 macOS가 합성 입력을 차단하는 대상은 지원하지 않는다.

## 테스트 요구사항

운영체제 API를 감싼 인터페이스를 두어 다음 동작을 단위 테스트한다.

- 매크로 UUID 중복 금지, 항목 순서 보존, 일반 키 범위와 보조 키 규칙, F13~F20의 단독·보조 키 조합 허용, F21~F24 단독 사용 허용과 보조 키 조합 거부, F25~F35 거부
- 설정의 빈 문자열, 중복 단축키와 10,000자 제한 검증
- 설정 저장 실패 시 기존 실행 설정 유지
- 활성화된 항목의 단축키만 등록하고 종료 시 해제
- 단축키 등록 일부 실패가 다른 항목에 영향을 주지 않음
- 필요한 F21~F24 HID usage만 매칭하고 권한 없음·시작 실패가 Carbon 단축키에 영향을 주지 않음
- F21~F24 활성화·비활성화에 따른 Input Monitoring 요청과 HID 모니터 시작·종료
- 실행 요청의 FIFO 순서와 단축키 수신 시점의 문자열·후속 키 복사
- Unicode 분할이 surrogate pair와 확장 자소 클러스터를 나누지 않음
- 텍스트 이벤트 전체 생성 뒤 후속 키가 한 번 게시되고, 사용자 지정 후속 키의 키다운·키업에 같은 보조 키 flags가 적용되며, 생성 실패 시 아무 이벤트도 게시되지 않음
- 권한이 없거나 문자열 조회가 실패하면 이벤트를 게시하지 않음
- 오류와 실행 상태에 매크로 문자열이 포함되지 않음
- 로그인 시 실행의 기본값이 비활성이고 사용자가 설정과 해제를 전환할 수 있음

실제 macOS 환경에서는 다음 대상을 수동 통합 검증한다.

- TextEdit
- Safari 또는 Chromium 입력 필드
- Terminal
- VS Code
- 한글 입력기가 활성화된 상태
- 여러 단축키를 빠르게 누른 상태
- Accessibility 권한이 없거나 실행 중 철회된 상태
- F21~F24 활성화 전후와 Input Monitoring 권한이 없거나 실행 중 철회된 상태
- 포커스된 앱이 원래 F21~F24 이벤트를 받을 수 있으며 앱이 해당 이벤트를 억제하지 않는 상태
- 다른 앱이 같은 전역 단축키를 사용하는 상태

## 수용 기준

1. macOS 13 이상에서 메뉴 바 앱이 실행되고 설정 화면을 열 수 있다.
2. 매크로 항목을 개수 제한 없이 추가·삭제·정렬할 수 있고, 항목별 활성화 여부, 유효한 전역 단축키, 최대 10,000자의 Unicode 문자열과 선택적인 후속 키 입력을 저장하고 다시 불러올 수 있다.
3. 일반 키 단축키에는 하나 이상의 보조 키를 요구하고 F13~F20은 보조 키 없이 사용하거나 보조 키와 결합할 수 있으며 F21~F24는 단독 사용만 허용한다. 일반 키 조합과 F1~F20은 `RegisterEventHotKey`로 등록하고 F21~F24는 해당 HID usage만 매칭하며, F21~F24를 사용하지 않을 때는 Input Monitoring 권한을 요청하지 않는다.
4. 한글 입력기가 활성화된 TextEdit에서 한글, 영문, 여러 줄, 이모지와 조합 문자가 설정과 동일하게 게시된다.
5. 후속 키를 설정하면 전체 텍스트 게시 뒤 지정한 Enter, Space, Tab 또는 사용자 지정 키 입력이 한 번 게시된다. 텍스트나 후속 키 이벤트 생성에 실패하면 해당 요청의 이벤트를 하나도 게시하지 않는다.
6. 빠르게 받은 여러 단축키가 누락되거나 순서가 바뀌지 않는다.
7. Accessibility 권한 없음, F21~F24에 필요한 Input Monitoring 권한 없음, 시작 시 설정 로드·검증 오류, 단축키 등록 실패 또는 HID 모니터 시작 실패 상태의 해당 항목에서는 이벤트를 게시하지 않는다. 편집 내용 저장 실패 시에는 저장 직전부터 유효했던 실행 설정과 트리거 상태를 유지하며, 해당 기존 설정의 단축키는 계속 실행할 수 있다.
8. 직접 입력 실패 시 클립보드 폴백이나 전체 문자열·후속 키 자동 재시도를 수행하지 않는다.
9. 로그와 화면 상태에 매크로 문자열이나 포커스된 앱 이름이 남지 않는다.
10. Release 빌드와 100자의 ASCII 문자열을 사용하고, 실행 큐가 빈 상태에서 이전 요청의 게시 API 호출이 끝난 뒤 다음 요청을 시작하는 방식으로 100회 측정해 단축키 수신부터 마지막 게시 API 호출 완료까지의 p50과 p95를 검증 기록에 남긴다. 큐 대기 시간과 대상 앱의 화면 반영 시간은 측정에서 제외하며 실행마다 외부 프로세스를 시작하지 않는다. 첫 버전은 환경별 기준값을 수집하는 단계이므로 통과 임계값을 두지 않는다.
11. 로그인 시 실행은 기본적으로 비활성이고, 메뉴 바에서 설정하거나 해제한 상태가 macOS 로그인 항목에 반영된다.
